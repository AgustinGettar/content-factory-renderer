POLICY

BALANCE AND JOURNAL
Only a parsed official Higgsfield HTTP 400/402/403 rejection with an allowlisted
machine code (insufficient_balance, insufficient_funds, credit_balance_exhausted)
and an error-only body is classified as insufficient funds. Generic 402/403,
429 rate limits, 5xx, timeouts, accepted/queued jobs and malformed/unknown
responses do not enable recovery. No real provider rejection was observed in
this implementation; tests supply explicit offline responses.
The journal first persists headers and then the parsed rejection. Checkpoint
recovery reconstructs PAUSED_INSUFFICIENT_BALANCE after a crash, without POST.
The durable pause contains target episode, stage, attempt, diagnostic request
ID when supplied, error code, checkpoint, reservation status and last-known
estimated/reserved/actual costs. Rejected-attempt reservations are preserved:
rejection does not manufacture a verified zero-dollar charge.
SALDO RECARGADO is contextual and routed through the existing canonical HMAC
endpoint, owner validation, delivered opaque token and CAS. It authorizes one
successor of that exact rejected attempt. Double clicks, fresh nonces and
restarts cannot authorize another successor. Ambiguous requests never qualify.
The original journal row, payload, review decisions and cost exposure remain.

OFFICIAL BALANCE
No official balance query is configured in the deployed integration's known
capabilities. The runtime therefore records OFFICIAL_QUERY_UNAVAILABLE with
provider_balance_usd = null. There is no guessed endpoint or login attempt.
A server-injected official balance reader is supported and tested: provenance,
USD, credential/account binding, nonnegative amount and <=60s freshness are
required; failure does not fall back to a claimed successful verification.
Without it, recovery requires the sealed supervised policy plus the explicit
callback consent. A top-up never changes the episode ceiling. Budget exhaustion
keeps the pause and asks for separate budget-increase authorization.

No new tables, endpoints, provider, scheduler, budget subsystem or worker.

to any Supabase project. PGlite is a pinned test-only development dependency.
Deploying the code without the migration cannot submit a second request;
the old unique scope rejects it. Apply the reviewed migration before enabling
this feature in staging, with separate deployment authorization.
