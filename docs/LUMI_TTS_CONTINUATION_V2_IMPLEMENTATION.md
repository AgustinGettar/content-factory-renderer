# TTS and canonical artifact continuation

Production acceptance remains BLOCKED. No provider generation is authorized.

## Deployed transport

The TTS executor accepts an injected Higgsfield transport. It does not require a
CLI, shell login, browser session or Work capability. The prior CLI wrapper was
removed: absence of a binary was an adapter assumption, not evidence that installing
it would authenticate the Render runtime.

Existing Image/Video requests use providerJson and HF_API_KEY with server-side
Higgsfield REST authentication. The successful historical Annie narration manifests
preserve text2speech_v2 / elevenlabs / preset requests, three completed job IDs,
credit quotes and original MP3 hashes. Those records do not contain the original
caller or internal connector implementation. We do not infer an equivalent public
API endpoint from a connector model name.

Until the exact TTS REST model, voice and cost contracts can be verified, an absent
binding fails with HIGGSFIELD_TTS_API_CONTRACT_UNVERIFIED. A missing configured
HF_API_KEY is reported separately as HIGGSFIELD_STAGING_CREDENTIAL_MISSING.
No credentials are copied, printed or changed. The strict preflight uses only a
bound client's non-generative quote and keeps provider credits separate from USD.
Readiness remains 13/14; request-only offline dry boundaries are not auth evidence.

## Canonical replay

The shared materializer accepts an existing artifact identity bound to an expected
SHA. It verifies and reuses that canonical storage object and artifact ID without
uploading another copy. Missing objects and storage errors fail closed. New results
retain immutable result-addressed storage and recover through the same receipt store.
The existing orchestrator owns artifact registry, normalized StageResult and
checkpoint continuation; no provider submission occurs in recovery.

The existing signed staging dry operation can replay one persisted Image/Video
completion or import a verified existing Library audio stem once into content-addressed
runtime storage. It uses Supabase recovery checkpoints and the existing CAS receipt
store. Diagnostics use isolated fictitious IDs, zero budgets, runners OFF and no
next-stage dispatch. Image Source QA and Video Temporal QA consume persisted
SHA-bound evidence; historical Human Review is preserved. No synthetic pixel review
is manufactured to make a gate pass.

## Audio panel

Audio delivery uses the existing media-first renderer and canonical message.
Transport-only historical audio exposes listen, details and HOME; no approval or
rejection action is available. Audio file_id is bound to the exact SHA after a
verified Telegram acknowledgment and reused. HOME and master cache/approval remain
independent. Lost-response reconciliation now recognizes audio and verifies size.

Local tests do not certify live Telegram behavior. The signed staging replay and
actual audio-to-photo transition must be measured before reporting their gates PASS.
The 14-stage metadata dry fixture is still explicitly diagnostic and is not a real
media end-to-end acceptance while the TTS transport remains unbound.
