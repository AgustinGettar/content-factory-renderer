# Lumi Trading — separate encrypted S3 recovery v1

This is strictly the **existing secondary PAPER** worker's recoverability, not a new bot or trading account. The worker on EC2 keeps running and writes its own SQLite state and three local SQLite daily snapshots exactly as before. This separate helper selects the newest existing `daily-[012].sqlite` snapshot, insists that it is less than 36 hours old, verifies `PRAGMA integrity_check`, verifies its PAPER account/revision, compresses and encrypts AES-256-GCM using **the already existing private backup key**, and uploads to private S3. It then downloads that exact remote object, checks SHA-256, decrypts and authenticates the entire GCM plaintext **as a streaming SHA-256 match against the already full-PRAGMA-integrity-checked local snapshot**, and checks source revision metadata. This is cryptographic byte-for-byte restore-equivalence without writing a second ~500MB SQLite file at every scheduled run; a full physical restore remains available via the explicit `--full-restore` option. No keys or raw positions are printed or placed in Git.

The bucket `lumi-paper-recovery-146766539818-eun1` is in `eu-north-1`. All public access is blocked; SSE-S3 encryption is configured. The EC2 role has only `s3:ListBucket` on `recovery/*` plus `s3:GetObject` and `s3:PutObject` on objects under `recovery/`. It cannot list/modify any other buckets by these permissions. No S3 deletion permission is granted.

Fixed remote keys `recovery/daily-0.lumi-gcm`, `recovery/daily-1.lumi-gcm`, `recovery/daily-2.lumi-gcm` match local daily rotation. At most three objects are retained by the helper; the latest successful version of each slot remains remotely if the next upload fails. There is no S3 object versioning. AWS S3 usage is metered and not guaranteed free; backup storage remains bounded to approximately three compressed backups (dependent on future database size).

## Background schedule and recovery

The standalone systemd **oneshot** `lumi-trading-s3-recovery.service` uses a private local helper at `/opt/lumi-trading/recovery/s3-backup.mjs`, as root only to read the existing root-owned key file and daily snapshots; no worker code is imported. Files and verified restores live in a mode-0700 temporary directory under the root filesystem `/var/lib/lumi-trading/backups/.remote-verify-*`, **not `/tmp`**, which is a separate 457MB tmpfs and too small to restore a ~494MB SQLite snapshot. Finally removes temporary files even after failure. The scheduled path bounds compressed ciphertext to 256 MiB and uses stream verification rather than materializing a ~500 MB restored database on every timer run.

The timer runs 00:25, 06:25, 12:25 and 18:25 UTC (random delay <=5min). If the most recent local snapshot is unchanged and the matching S3 object metadata already has its size, mtime, revision and SHA-256, the regular scheduled invocation does nothing and does not consume CPU or network for another restore. Operators can run `node /opt/lumi-trading/recovery/s3-backup.mjs --verify-existing` to force remote download, GCM decryption and plaintext hash verification; add `--full-restore` to also materialize a restored SQLite file transiently and execute a separate full `PRAGMA integrity_check` and revision check.

For full recovery to another instance: **stop the replacement writer first**; download the correct remote `.lumi-gcm` object, verify SHA-256 metadata, decrypt with the original 32-byte AES key in private config, validate SQLite integrity and revision, then restore with correct ownership/perms before starting. Never overwrite a live SQLite file, and never copy a live database without its WAL. A valid backup is not permission to clear the history or restart the original worker.

The old site/R2 backup publisher may continue reporting `BACKUP_SIZE_LIMIT` for its separate 16MiB limit: this new verified S3 path fixes off-instance recoverability **without changing the private site's API**. The panel's existing backup status must not be relabeled from the old R2 success marker without adding a separate evidence field.
