# Read-only operational monitor repair

The operational adapter changed laboratory.active to the futures execution version but supplied decisions keyed by pattern names. Existing timeframe cards read numeric timeframe keys and diagnostics. The missing compatibility fields therefore looked like zero evaluations and no timestamp, although committed secondary decisions existed. The publisher also projected inside send(): a new commit between the live and detail uploads could cause the latter to fall back to an unextended snapshot.

This repair changes only the read model and its publication. The normal snapshot builds its operational view synchronously from one decoded committed row before any network await. Both channels retain that row's revision and decision timestamp. The transport compatibility wrapper recognizes already projected payloads and does not reread SQLite. Contract tests simulate a commit occurring during the first upload.

The monitor now provides numeric 5m decision/diagnostic keys, the genuine latest context-use timestamp for 15m, per-pattern reasons, and an explicit count unit: pattern checks, not candles or executed trades. No heartbeat substitutes for a decision time. Missing values stay unknown; stale decisions stay stale. Skipped windows do not claim a context read. There are no fabricated entries, wins or probability values.

The pre-existing 1m/15m/1h/4h source metadata is preserved separately as primary_timeframes. Period choices are retained and 5m added; old non-operational periods carry an explicit legacy-context explanation rather than a claim that they are awaiting a new secondary entry. 15m is context, not an independent entry engine. Futures bar counts are shown only when the read-only runtime inventory matches the committed close; spot bar counts are never relabelled as futures. Archived trial results are not mixed into the current trial.

No change to entry rules, broker, fees, leverage, risk budgets, stops, exits, account balances, trial history, Telegram transport or existing primary evaluation stream. The worker's only wiring change passes the already running secondary feed for read-only inventory. All tests run outside the live AWS worker; deployment must check an unchanged execution fingerprint and a flat account before restarting. This fixes the API contract; rendered client validation must be reported separately from endpoint verification.
